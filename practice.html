Rapid fire

What is the difference between Senior Developer and ATL?

Scope of ownership. A Senior Developer mainly owns implementation and quality of assigned work. ATL also considers cross-module impact, technical decisions, delivery risk, team consistency and production outcome.

Give me one production issue you solved.

Use the MySQL/strace story: node-specific high load → process/query evidence → strace → looping process → safe correction → verify utilization.

What technical decision did you make recently?

GraphQL caching with dynamic TTL. Discuss performance benefit versus freshness/invalidation complexity.

What have you changed that the team now uses?

Project release-review workflow and reusable AI/project rules. Keep the answer factual and add adoption count only if known.

How do you know your automation adds value?

Every changed file in the generated release diff is listed and can be checked for ownership/ticket mapping. Additional metrics to track are review time, releases processed, unexpected files found and issues caught before production.

Why should I trust AI-generated review?

You should not trust it blindly. The Git diff and source code remain the source of truth. AI structures findings; developers validate and approve.

How do you decide what should block a release?

Block when there is unresolved functional/security/data-integrity risk, failed mandatory validation, unclear ownership of risky changes, or insufficient evidence that critical affected flows were tested.

How do you handle disagreement with your review?

Return to requirement, evidence and trade-offs. If unresolved, summarize options and impacts and involve the appropriate lead.

Build, buy or reuse?

Compare required capability, implementation effort, maintenance, integration risk and cost. The synthetic-monitoring R&D is your evidence.

What metrics would you track as ATL?

Delivery predictability, production defects/incidents, review/release leakage, key service performance, testing effectiveness, recurring issue patterns and the measurable impact of process/automation improvements.

AI-heavy CTO questions

What is RAG and where would you use it?

RAG retrieves trusted relevant information at request time and supplies it as context to the model. Use it when the model needs current/private domain knowledge that should come from controlled sources rather than memory alone.

What is MCP?

A standardized protocol for exposing tools/context to AI applications. The engineering questions are authentication, authorization, tool scope, data exposure and auditability.

What makes an AI system agentic?

It can pursue a goal across multiple steps, select tools/actions based on observations and adapt its path. That autonomy increases the need for permissions, limits, audit logs and approval boundaries.

Prompt engineering vs context engineering?

Prompt engineering shapes the instruction. Context engineering also manages which documents, rules, history, tools and state are supplied so the model has the right information to act correctly.

How would you evaluate an AI coding workflow?

Correctness, security, false positives, missed issues, developer acceptance, time/effort, reproducibility and whether humans can understand and audit why it made a recommendation.
